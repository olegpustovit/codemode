What changed between the old and new versions

The work changes the agent’s execution path, not just the code’s organization.

A1–A2 · INPUTS & ERRORS

Fewer avoidable correction turns

Old: optional nonnullable arguments such as cursor=None failed validation; typo errors gave little guidance.
New: omit only optional top-level nulls the schema rejects; preserve required/nullable/nested values. Catchable signatures and scoped nearest-name suggestions help the agent recover.
Measured: execute errors fall from the proposal’s ~17% to 2.6634% in E5 off. This is a package-level result, not an isolated A1 effect.
A3–A4 · LIMITS

The documented budget is usable

Old: sequential calls stopped at 55; initialization and tool listing competed for a 60/min token limit.
New: 100 sequential or parallel calls; the 101st produces a catchable limit error. Admission counts tools/call per session, default 600/min, with atomic higher-level ceilings.
Verified with real-worker/broker regressions and concurrent eval evidence. Live release safety smoke passes.
B1–B4 · DISCOVERY

Search and inspect inside the execution

Old: repeated external searches and verbose output types inflated context.
New: await tools.search, synchronous help with parameter descriptions, scoped source manifests, compact stubs and bounded structural truncation summaries.
Observed: 6 → 3 outer calls and ~52.5% less total input in the shared old/new comparison.
B5 + C1/C4 · DATA

Page and project without feeding every row to the model

Old: the agent managed page loops and received large row payloads.
New: schema-derived .all(), bounded page/call limits and _fields projection inside workers. Each upstream page remains validated, scoped and audited.
Heavy tasks are correct, but the measured 2× cost target is still unmet. Do not infer a cost win solely from feature availability.
C2–C3 · REUSE

Session memory and source recipes

Old: more identifiers and workflow code had to be reconstructed.
New: bounded 64 KiB session memo, expiry/tenant isolation, saved-script arguments and source recipes that respect scope and edits.
Functional coverage passes. No experiment isolates how much each feature contributes to the headline gains.
D1–D4 + E5 · CLIENT SETUP

A measured Codex execution profile

Old: generic server identity and setup; client deferral could add discovery overhead.
New: Codemode/build identity, short execution guidance, token setup receipt and qualified two-tool exposure settings for Codex 0.169.0.
Matched E5: deferral off passes all six standard targets; on remains 120/120 correct but misses time and uncached-input targets.

How much can we attribute to the refactor?

There is a real observed gain. The measurements do not support attributing all of it to code cleanup alone.

E1: bug fixes alone were insufficient

A1+A2-only counterfactual: 120/120 correct, but median 6 calls, 108,711.5 input tokens, 25.5 s and 8.55% execute errors. The broader discovery/runtime/client package is needed to reach the final standard targets.

E5: client configuration matters

On/off treatments were interleaved over the same candidate. Both pass 120/120. Deferral on: 20.45 s, 15,181 uncached tokens. Off: 16.95 s, 13,755 uncached tokens. Some improvement comes from the client exposure profile, not server code alone.

Heavy-data cost: useful savings, target missed

Read the comparison correctly

  • The three-way chart joins 38 task names present in all arms, with three repeats each. It pools the 114 raw runs per arm for summary medians; per-task rows use three-repeat medians.
  • The original baseline is evals-40-merged.json from release 2f23413. New Codemode is E5 off, Codex 0.169.0, candidate binary 95a90c44…; the released binary adds tested setup copy after this cohort. The final ARM release was not rerun as a full three-way cohort.
  • The baseline model is recorded as “codex default”; exact model equality is unproven. Client config, cache state and elapsed-time conditions differ. These are descriptive before/after results, not a clean causal server-only speedup estimate.
  • All shared-comparison attempts pass, but other experiments have failed attempts, false-negative graders and interrupted probes. Those remain in the archive; the report does not claim every experiment ever run passed.
  • Search-size behavior is not exercised by the no-external-search E5 cohort. Provider consent and owner external-client acceptance were not performed. No claim of fully met performance targets is made.
