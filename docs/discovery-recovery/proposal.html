Codemode v6 · post-mortem · 17 Nov 2026

v6 worked on Moneybag and broke on Nudge. The cause is one starved manifest plus a search that can't find "status".

The headline medians hide a split. Tasks whose tools fit in the new signature manifest got much cheaper. Nudge and cross-app tasks lost their status tool from the manifest. The model then guessed names that full-text search cannot match, and looped.

Moneybag shows the design works: mb-oct-groceries, mb-sept-groceries, mb-create-account and mb-bulk-payees are now one call. Nudge and cross-app make up 54 of the 120 runs, so their regression cancels the gain in the pooled median.

Root cause 1: the manifest budget is first come, first served

catalogue.rs manifest() walks sources alphabetically, and each source may take whatever remains of the 3,072-byte budget. Artifacts and Moneybag go first and get 5 signatures each. Nudge comes last and its signatures are long (create_issue has about 10 args), so it gets only 3: list_issues, get_issue, list_teams.

list_issue_statuses and create_issue are cut. Yet almost every Nudge task needs a status ID.

Root cause 2: search has no stemming, so guessed names miss

With the tool gone from view, the model guessed. The catalogue uses websearch_to_tsquery('simple', …), which matches whole tokens only. status never matches statuses, and made-up names like list_statuses match nothing.

The top v6 query, nudge status, was sent 35 times and found the tool 0 times. A miss doesn't end with an error. The model gets back a plausible-looking list (create_issue first, because its description says "status") and tries again.

A typical run, nudge-backlog-count, took 7 executes and 145k tokens, against 4 calls and 59k in E5: list teams → search "nudge status" → probe issues → search "nudge" → get_team → search 3 invented names → work.

Root cause 3: probes didn't go away

Raw print(...) executes per run barely moved: Artifacts 2.9 → 2.8, Nudge 2.1 → 2.1, cross-app 2.0 → 4.1. W2's shape feedback only fires after a key, type or index error, and models print before they index. Artifacts' list tool declares a generic object, so its skeleton just says dict and gives the model nothing to go on.

Confounders: why wall time looks worse than the mechanism suggests

  • The model changed. E5 ran "codex default". v6 pins gpt-6.1-sol. The time and token deltas are not a same-model comparison.
  • Jobs and cache setup changed. v6 adds warm-up and blocked arms, and the cache ratio rose from 73.2% to 78.2%. Uncached comparisons are not like for like.
  • The new direct arm is the Codex host, now at 19.8 s. v6 at 19.3 s is roughly level with it, not behind.

Fixes, smallest first

#ChangeWhereSize
1Fair manifest budget. Split 3,072 B evenly across sources, or fill round-robin by rank, so every source gets its top tools. Add bare names for ranked tools that miss the cut ("also: list_issue_statuses, create_issue"). Names are cheap and were enough in E5.catalogue.rs:226–250~20 lines + test asserting every source gets ≥ its rank-0–2 tools
2Forgiving search. Match terms as prefixes (status:*), and split identifiers so list_statuses → list & status:*. When nothing matches, return nearest-name suggestions (trigram on path, already used for unknown-tool errors) instead of an unrelated list.catalogue.rs:167–168, stubs.rs search_wordsquery builder + 2 regression cases (nudge status, nudge list_statuses)
3Shape before the model asks. When an execute prints a raw tool reply over ~2 KB, append its shape skeleton. Learn skeletons for generic-dict tools from the first live reply.execution/shape.rs, output pathsmall; reuses summarize()
4Same-model A/B. Rerun E5's binary with pinned gpt-6.1-sol, blocked arms and warm-up before judging time.codemode-evalsconfig only

Expected if 1 and 2 land: Nudge and cross-app move back to at least E5 levels while Moneybag keeps its gains. That alone should bring the pooled medians to about 2–2.5 calls and well under 50k tokens. This is an estimate; check it with a Nudge-only 42-run cohort first, since that is a cheap signal.
