Codemode · proposal v6 · after agent-efficiency release · 17 Nov 2026

Agents still pay a "look first" tax, and the heavy-cost control was already code mode.

I reread all 120 qualified E5-off transcripts and the 5k-row heavy pack. The surprising results have four root causes. Three can be fixed with small changes. The fourth is in the measurement, not the gateway.

What surprised us, and why

Each finding comes from the archived runs in codemode-evals/results. Numbers are counts over the 120 deferral-off runs, unless a row says otherwise.

RC1 · the 3-call floor

Agents use execute like a REPL

114 of 120 runs start with an execute that only searches. 94 of 141 searches (67%) look up tools the manifest already names. The model already knows the names. It is looking for signatures. Our own guidance says Use one execute per step.

RC2 · the probe turn

Output shapes were removed, so models print raw results

B3 dropped output TypedDicts to shrink search results. Now 70 of 413 executes (17%) are just print(await tools.x.y(...)), run to learn the keys. The next execute then does the real work.

RC3 · the 2× heavy target

"Direct MCP" was not raw MCP

Codex 0.169 ships code_mode_host as stable and on, with host-side output truncation. The direct arm paged 53 times through 7.07 MB of results, used just 75.7k input tokens, and still got exact sums. The control arm was already filtering in code.

RC4 · the uncached-token jitter

Prompt-cache hits behave like a lottery

safety-token makes no tool calls and sends an identical prompt each time. In E5-off it got 0, 0 and 9,088 cached tokens. In the old cohort it got 8,320 every time. The median cache ratio fell from 0.849 to 0.732, and p10 fell from 0.775 to 0.461. Several per-task "regressions" are cache misses.

What a typical run looks like today

# call 1: discovery (names were already in the manifest)
print(await tools.search('artifact_list OR artifact_read'))
# call 2: probe the shape
print(await tools.artifacts.artifact_list(q='eval-seed-alpha'))
# call 3: the actual work
print(await tools.artifacts.artifact_read(id='r0bg…', format='markdown'))

This is art-budget, run 7a047f. All three steps fit in one execute, which is the point of code mode.

Why it matters: each extra MCP call is one more model turn. That costs about 4–5 s and resends the whole context. Going from 3 turns to 2 is the biggest remaining lever on time, total tokens and uncached tokens.

This explains both heavy-pack surprises. The control's cost stayed flat from 1k to 5k rows ($0.0601 → $0.0588) because Codex's host already filtered the rows. Codemode rose from $0.0303 to $0.0480. Its per-task uncached input is bimodal: heavy-nudge sits at ~13.6k in some runs and ~25k in others, which points to cache misses (RC4) rather than row count. Codemode cannot be 2× cheaper than another code mode on the same work. The target was set against the wrong baseline.

To verify: codex features list → code_mode_host stable true, code_mode_host_output_truncation stable true. The heavy-large transcripts show no code_mode warning in the direct arm, so the host was on by default and not by our flags.

RC4: cache hits are a lottery the metric treats as signal

Cache ratio per run (cached ÷ input)

Likely mechanism

  • E5 ran 8 jobs in parallel and interleaved two prompt prefixes (deferral on/off). That gives two cold prefixes competing for cache routing.
  • Codex keys the cache per thread. Each run's first request only hits the cache if a sibling warmed the same prefix on the same route.
  • One miss costs about 9–10k fresh tokens. That is as large as the whole effect we are trying to measure.
  • The prefix also changes whenever a source syncs, because the manifest is part of both the instructions and the execute description.

Plan: four small waves

No new MCP tools. /mcp stays exactly search + execute. Most of the work is prompt surface and one error-path change. Each wave ships through the eval gate.

W0 · ½ day · measurement first

Fix the yardstick

  • E8 three-arm heavy pack: raw MCP (features.code_mode_host=false), Codex host (default) and Codemode.
  • Warm each prefix with one discarded run, then run arms in blocks rather than interleaving them.
  • Report fresh_after_first (uncached tokens excluding the first request) next to raw uncached.
  • Add the S/W execute classifier from this analysis to summarize.py as a gate metric.

Repo: codemode-evals/evals/run.py, summarize.py, heavy_cost.py

W1 · 1 day · kill the discovery execute

Signatures in the manifest, "one execute per task"

  • The manifest's top tools per source (already ranked in SQL) carry their brief input signature plus an output key skeleton, about 3 KB total and cached in the prefix.
  • Rewrite the guidance from Use one execute per step to "Do the whole task in one execute. Call listed tools directly; a wrong argument raises ToolError with the signature."
  • Put the manifest in one place only (description or instructions, using E2's winner) to cut prefix bytes.

Code: catalogue.rs:75 manifest() (add stub_brief to the query), gateway/src/server.rs:162, :318

W2 · 1 day · kill the probe execute

Shapes in errors and in signatures

  • When an execute fails with KeyError/TypeError/IndexError, append the structural shape of the last tool results. This reuses execution/shape.rs summarize(), which already exists. The retry then needs no extra probe.
  • Brief stubs regain a one-line return skeleton such as -> {artifacts:[{id,title,kind,…}]} rather than full TypedDicts. This keeps B3's size win.
  • Use _fields in the description's example so projection becomes the default habit.

Code: catalogue/stubs.rs, components/execution/shape.rs, the error path in execution.rs

W3 · ½ day · re-baseline

Re-measure and reset the heavy target

  • Run the full 40×3 standard pack plus E8 heavy, both on Codex and Claude.
  • Replace "≥2× cheaper than direct" with two targets: ≥2× vs raw MCP and ≤1.0× vs the Codex host.
  • If W1 or W2 regress correctness, ship only the wave that passes. Each wave is gated on its own.

The targets are estimates. The 2-call target assumes W1 removes most S executes and W2 removes most probes. Claude already reaches 11.45 s with 3 calls, which suggests the turn floor, not gateway latency, dominates.

Risks and guardrails

Bigger prefix

About 3 KB more manifest is cached after the first request. Cap it by byte budget, and drop the duplicate copy (W1) to stay net-neutral.

Bolder agents, more errors

Calling tools directly may raise the error rate. That is acceptable only if errors are recovered in the same or the next turn. The gate tracks recovery, not just the error count.

Shape leaks

Shapes show keys and counts, never values (shape.rs tests already assert this). Workspace scope, blocks, audit and the 100-call cap are unchanged.
