Codemode · control plane proposal · v8 · 2026-11-14

A desktop-grade control plane with a console soul.

The prototype above is the proposal. Try it with the keyboard: ↑↓ move, ↵ or → opens a pane, Esc or ← closes it, [] switch tabs, V switches the Sessions layout, 1–5 switch sections, / searches.

  1. Fix linking. GitHub can't work with today's flow. Nudge's real error is being thrown away.
  2. Integrations. 41 vendors, searchable, each with a connection method verified against the real provider.
  3. Sessions. Each agent's executions grouped automatically, with results kept for 4 days.
  4. Approvals deleted. Tools are either allowed or blocked.
  5. Panes that stack. Lists start full width. Opening something slides a pane in from the right and keeps the path visible. Sessions also has a 4-day timeline layout.

01

UX model

The control plane has four jobs. Each one gets a screen with the same shape: a table in the middle, the selected item's detail on the right, and results plus available keys in the status bar. Learn one screen and you know them all.

Transitions each one answers "what changed?"

  • Section: the backdrop crossfades to the section color (600 ms), the header fades and the rows rise in with a 16 ms stagger.
  • Tab: the underline glides to the new tab and the rows rise with half the stagger. Same place, different filter.
  • Selection: one cursor glides between rows (200 ms). If a deeper pane is open, it follows the selection with a 120 ms fade, so you can flip through executions with ↑↓.
  • Open (push): a pane slides in from the right while the panes behind narrow (320 ms) and dim to 78%. Back (pop): the top pane slides out and the rest widen. The breadcrumb mirrors the stack, and each crumb jumps back to its level.
  • Layout switch: List ↔ Timeline re-enters the rows with a stagger. Same data, different shape.
  • Every duration and curve is a token. Under prefers-reduced-motion all of it is instant.

Interaction rules

  • Click opens, arrows browse. A click opens the next pane. ↑↓ moves the selection, and any open pane follows it.
  • → or Enter goes deeper, ← or Esc comes back. [ and ] switch tabs, and V switches the Sessions layout.
  • The status bar always lists the keys that work in the current context, and each one is also clickable. Detail actions show their key too.
  • The URL records state (section, tab, selection, drill-down) through TanStack Router search params, so Back works and any view can be linked.
  • Status is a word, not a dot. LINKED, NEEDS LINK, FAILED · STEP 6. Only failure gets color.
  • Errors say where, what and what next. The step, the provider's message verbatim, and the action that fixes it.
  • No modals. Destructive actions ask for a second press within 3 seconds, prompted in the status bar. Results appear there too, instead of toasts.
  • Live without sockets. The Sessions list refetches every 5 s while visible (TanStack Query), so new runs appear at the top.

02

What broke

I checked the production logs, the database and both providers' public discovery endpoints. I did not register clients or grant consent anywhere. Linking an account takes seven steps:

GitHub

The MCP endpoint points to github.com/login/oauth, which publishes no server metadata (404) and has no automatic client registration. The current flow requires one of the two, so it can never work for GitHub. Fix: paste a fine-grained token (already supported), or register your own GitHub OAuth app once.

Nudge

Steps 1 to 3 check out against the live endpoints, and registration is offered. The failure is somewhere in steps 4 to 6, but accounts/oauth.rs converts about 20 different errors into one generic Error::OAuth and logs nothing. Fix: keep the step and the provider's message, log it, show it, then fix the real cause.

Noise

Unlinked sources retry sync every 60 s and log 3 lines per source each time. Fix: skip them and show NEEDS LINK. New sources get lowercase slugs, so agents write tools.nudge, not tools.Nudge.

03

Integrations

One screen replaces Sources and Accounts. The list is grouped by category, and search matches vendor names, categories and, for linked sources, tool names (so "create issue" finds GitHub, Linear and Jira). The value column shows link state for vendors you've added and the connection method for the rest.

MethodWhat happens on EnterExamples
One-clickDiscovery plus client registration, then the provider's consent page. This is today's flow, minus the swallowed errors.Notion, Linear, Sentry, Atlassian, Stripe, Vercel
OAuth appThe provider has no client registration. Register an app once at the vendor and paste its ID and secret, which are sealed per tenant. After that, linking is one click.GitHub, Slack, Google

Registry: crates/core/integrations.json is embedded in the binary and served at /api/integrations, and /mcp-admin reads the same file. Probe: tools/probe-integrations runs discovery only (never registers, never consents) and fails qualification when an entry's declared method doesn't match the provider. That is what stops "nothing works" from happening again. Icons: simple-icons (CC0) per-icon imports, drawn as white glyphs in the list and as large line art in the detail panel. The vendors shown are a starting list; the probe decides what ships.

04

Sessions → executions

A session is a run of executions from one agent grant and workspace, with no gap longer than 30 minutes. The gateway infers sessions itself, so agents change nothing. Each execution now keeps its return value, stdout and per-call result previews, which execute already computes and currently discards. Everything is deleted 4 days after the session's last activity.

Titles without an LLM

An execution's title is its first # comment, otherwise its tool paths in call order (sentry.list_issues → linear.create_issue). A session's title is its first execution's title, and you can rename it. The client name comes from the OAuth client metadata or the token label.

Stored

Code (≤ 64 KB), result (≤ 16 KB), stdout (≤ 16 KB), and per call: redacted args plus a ≤ 2 KB result preview. Stored unencrypted by your decision, scoped by tenant RLS. The nightly backup keeps a copy until it rotates out.

Retention

expires_at = last_seen_at + 4 days. An hourly sweep deletes expired sessions and cascades to their executions and calls, using the same pattern as sessions.sweep(). The detail panel shows the time remaining as a fact, not as a progress bar.

Layouts V switches between them

  • List: scan by title, agent, counts and status, grouped by day. Best for "what failed?"
  • Timeline: the 4-day retention window drawn to scale. Each session is a bar, each execution a tick, and failures are rose. The left edge is where sessions expire. Best for "what ran overnight?" and for spotting overlap.
  • Drill-down: session → executions → execution, as stacked panes. With an execution open, ↑↓ steps through executions while the code and result update in place.
05

Approvals: deleted

Agents run headless. Nobody is there to click approve.
  • Every tool is allow or block, and the default is allow. A blocked call raises PermissionError in the agent's Python, naming the tool and workspace.
  • Migration: ask → allow. Drop paused_runs and approval_calls, the Approvals page, approval_url and the pause-only snapshot signing.
  • /mcp goes from three tools to two: search and execute. About 1,000 lines deleted. AGENTS.md drops the approval and replay rules.
06

Visual system

The layout is a standard desktop web app. The atmosphere comes from three layers behind it: a live shader backdrop, a color per section, and light used only to mark focus. Everything is driven by tokens (§07).

Backdrop

A WebGL1 fragment shader of about 40 lines draws the wave as a ribbon of strands that pinches and twists as it drifts, with a fainter second ribbon behind it. Strands curl through a flow-field warp, and a pulse of light travels along them. A slowly wandering depth of field keeps only a few strands sharp and blurs the rest, so text over the ribbon stays readable. Each strand is a soft gaussian sampled twice per pixel, and where strands bunch up they blend into a glow, so there is no aliasing or moiré. Section colors are deep (cobalt, violet, teal, bronze, crimson) and only tint the field. It renders at device resolution, capped at 2×. It pauses when hidden, draws one static frame under reduced motion, and falls back to a dark gradient without WebGL.

Light

Glow marks one thing at a time: the current nav item, the selection cursor, the active tab, or the primary button on hover. There are two tokens, --glow-1 and --glow-2, both at 45% alpha or less. Only the selected row's name glows. All other text stays flat.

Type

M PLUS 1p, a free Japanese gothic with a console-era feel, at 400 or 500 for everything you read. Weights 200–300 appear only at 28px and up. The hierarchy runs from 28px page title to 13px tabs, 14px rows and 11px caps labels. JetBrains Mono is for code, IDs and counts.

  • Square edges everywhere. Surfaces are separated by 1px lines, not radius or shadow.
  • Status is a word. Only failure (rose) and attention (amber) get color.
  • Legibility: body text holds ≥ 4.5:1 against the work surface at the brightest point of the backdrop. Labels use --c-text-3 (56%), never lower.
  • Removed: dark overlay surfaces, cards, glass, pills, status dots, drop shadows, rounded corners, modals and toasts. Surfaces are transparent, separated by 1px rules, and a 1px text shadow keeps text crisp over the lines.
07

UI kit

The prototype is built from these tokens and components. In ui/ they replace Card, Badge, Alert, Sheet, Sidebar and Toaster. Button, Input and Table are restyled through the tokens. New components: AppShell, SectionNav, TabBar (gliding underline), DataList (one cursor plus a useListNavigation hook with aria-activedescendant), PaneStack (push and pop with animated widths), Timeline, Facts, StatusBar and Backdrop. Tokens live in ui/src/index.css as CSS variables mapped onto the shadcn variable names.

Session assignment one statement at execution start

WITH s AS (UPDATE agent_sessions SET last_seen_at=now() WHERE id=(SELECT id FROM agent_sessions WHERE token_id=$1 AND workspace_id=$2 AND last_seen_at > now()-interval '30 minutes' ORDER BY last_seen_at DESC LIMIT 1 FOR UPDATE) RETURNING id) SELECT id FROM s UNION ALL SELECT id FROM (INSERT INTO agent_sessions(token_id,workspace_id,client) SELECT $1,$2,$3 WHERE NOT EXISTS(SELECT 1 FROM s) RETURNING id) n;
